# Agent-first 전환 구현

`docs/agent-first.md`의 첫 구현 범위를 현재 Next.js 앱에 적용했다. `/storage`는 대화 기록과 하단 입력창으로 구성한다. 검색 결과, 사진 후보, 변경안과 저장 결과가 대화 안에 표시되고 직접 관리는 필요할 때 창을 열어 사용한다. 개인 키 정책은 사용자 요청에 따라 OpenAI와 Gemini 모두 암호화 보관한다.

## 적용 순서

1. Node 22, pnpm 10.10.0 환경에서 기존 로컬 인프라를 시작한다.
2. `supabase migration up --local`로 `00008_ai_providers.sql`, `00009_storage_actions.sql`, `00010_media_owner_cleanup.sql`, `00011_transcription_quota.sql`, `00012_bulk_item_move.sql`을 적용한다. 운영에는 배포 전 다섯 마이그레이션을 순서대로 별도 적용해야 한다. 이번 작업은 운영 DB를 변경하지 않았다.
3. 서버의 `SUPABASE_SERVICE_ROLE_KEY`와 기존 `GEMINI_KEY_ENCRYPTION_SECRET`를 유지한다. 공통 이름 `AI_KEY_ENCRYPTION_SECRET`도 지원하지만 기존 암호문을 읽으려면 동일한 32바이트 base64 비밀값이어야 한다.
4. 설정에서 개인 OpenAI 키를 등록한다. `.env.local`의 `OPENAI_API_KEY`는 로컬 개발 앱·로컬 Supabase에서만 **개발용 키 가져오기**로 로그인한 사용자에게 암호화 저장할 수 있다. 환경 키를 배포 사용자에게 자동 공유하지 않는다.

서버 전용 선택 설정:

| 변수 | 기본값 | 용도 |
| --- | --- | --- |
| `OPENAI_CHAT_MODEL` | `gpt-6-luna` | 텍스트 응답·도구 호출 |
| `OPENAI_VISION_MODEL` | `gpt-6.1-terra` | 사진 후보·저장 사진 재분석 |
| `OPENAI_MODEL` | 없음 | 용도별 모델 변수가 없을 때 사용하는 기존 공통 설정 |
| `OPENAI_TRANSCRIPTION_MODEL` | `gpt-transcribe` | 녹음 파일 → 입력창 텍스트 |
| `OPENAI_REALTIME_MODEL` | `gpt-realtime-2.1` | WebRTC 음성 세션 |
| `AI_KEY_ENCRYPTION_SECRET` | 기존 Gemini 암호화 비밀값 사용 | 공급자·사용자별 AES-256-GCM |

일반 API 키, 암호문, 사진 원본은 응답·로그에 노출하지 않는다. 모델 접근 권한은 개인 OpenAI 프로젝트에 따라 달라질 수 있다. 사진 공급자는 화면에서 명시적으로 선택하며 다른 공급자로 자동 전환하지 않는다.

## 변경 실행 계약

- 공통 `/api/storage` 서비스와 `storage_actions`가 등록·수정·이동·삭제·장소·보관함 변경을 처리한다.
- 준비 단계는 서버가 소유권과 현재 버전을 읽고 `action_id`, `revision`, `expected_versions`, `payload_hash`, `idempotency_key`, 전후 미리보기를 저장한다.
- 확인은 저장된 최신 변경안의 버전·해시·요청키를 모두 검증한 뒤 한 DB 트랜잭션으로 실행한다. 같은 요청의 재전송은 기존 영수증을 반환한다. `NULL` 승인값도 거부한다.
- 보관함 삭제는 내용물 버전을 함께 비교한다. 직접 DB·기존 폼·일괄 등록도 버전 트리거와 사용자별 쓰기 잠금에 참여한다. 확인 이후 물품이 추가되면 다시 확인해야 한다.
- 업무 충돌은 `PT409`를 사용한다. PostgreSQL 직렬화 오류 `40001`은 PostgREST 내부 재시도를 유발하므로 업무 충돌에 쓰지 않는다.
- 텍스트·음성 도구는 조회, 사진 후보 정정, 변경안 준비와 취소만 제공한다. 모델에 확정 도구나 SQL 접근을 주지 않는다. 실제 저장은 화면 확인 버튼으로만 진행한다.
- 사진 초안은 사진 ID와 편집 버전으로 연결한다. 다른 사진의 변경안이나 오래된 AI 응답이 현재 편집을 덮어쓰지 않는다.
- 응답 유실 시 확인한 변경안을 잠그고 동일 요청으로 재시도하거나 상태를 조회한다.

## 사진·검색·음성

새 사진은 비공개 `item-images` 버킷의 `media_assets`로 관리하고 `item_media`로 여러 물품에 연결한다. 사진 보관은 선택 사항이다. 업로드·물품 연결 상태를 분리하고 최종 연결은 물품 등록 트랜잭션에 포함한다. 다른 참조가 남아 있는 사진은 삭제하지 않는다. 미참조 사진은 24시간 유예 후 작업 화면 진입 시 정리하며 실패한 스토리지 삭제는 큐에 남겨 재시도한다. 사진 URL은 10분간 유효하며 새로고침으로 갱신한다.

계정 삭제 시 사진 참조의 외래키 검사는 트랜잭션 종료까지 미뤄 전체 소유 데이터의 연쇄 삭제를 허용한다. 사용 중인 사진만 단독 삭제하는 것은 계속 차단한다. 관리자가 계정을 삭제할 때는 해당 사용자의 Storage 파일을 먼저 제거해야 한다. DB 연쇄 삭제는 실제 파일을 제거하지 않는다.

장소 조회는 `list_locations`와 `get_location`으로 장소 → 보관함 → 물품을 구분한다. 빈 보관함도 조회에 남으며 `no_containers`(보관함 없음)와 `empty_containers`(보관함은 있고 물품 없음)를 별도 상태로 반환한다. 장소 이름과 보관함 이름이 함께 일치하면 구분 질문을 한다.

검색은 이름·설명을 단어별로 비교한다. 예를 들어 `검은색 충전기`는 `검은색 USB-C 충전기`를 찾는다. 기본 찾기 범위와 등록 대상은 분리된다. 위치는 현재 기록의 장소 → 보관함 경로이며 사진에는 등록 당시 사진임을 표시한다. 초기 목록은 1,000개까지 표시하고 초과 여부를 안내한다. 보관함 삭제는 전체 영향 목록을 수집하며 10,000개 초과는 한 번에 삭제하지 않는다.

기본 마이크는 음성 전사만 수행한다. 최대 60초·10MB 녹음을 `/api/agent/transcribe`로 보내 텍스트를 입력창에 추가하고, 사용자가 직접 전송한다. 녹음은 앱에 저장하지 않으며 사용자 암호화 키와 전사 전용 30회/시간 제한을 사용한다. 변환 중 타이핑·한글 조합·취소·화면 종료를 처리한다. 브라우저의 권한 요청이 응답하지 않아도 취소·30초 시간 초과 시 앱의 대기는 끝난다. 뒤늦게 허용된 마이크는 해제하며, 세션 교체 시 화면 상태와 오류를 초기화한다. 실시간 AI 응답은 별도 `음성 모드`에서만 시작한다.

Realtime은 서버에서 사용자 키를 복호화해 SDP를 교환한다. 브라우저에는 일반 키를 전달하지 않는다. 음성 도구는 같은 인증·소유권·변경 계약을 사용한다. 종료·실패·보기 전환 시 오디오 트랙을 정리하고 사진·대화 초안을 유지한다. 연결은 10분 후 종료하며 도구 호출 반복에도 상한을 둔다.

## 검증

```sh
pnpm test
RUN_AI_INTEGRATION=1 RUN_STORAGE_INTEGRATION=1 RUN_AGENT_INTEGRATION=1 RUN_TRANSCRIPTION_INTEGRATION=1 pnpm test
pnpm lint
pnpm build
pnpm audit
supabase db lint --local --schema public --level error
```

최종 검증은 Node 22.18.0 / pnpm 10.10.0에서 수행했다. 마이크 상태 복구, 마크다운, 모델 분리와 장소 계층 조회 수정 후 통합 테스트를 포함한 91개가 모두 통과했다. lint는 오류 0개(기존 ContainerForm의 React Hook Form 경고 1개), production build도 성공했다. `react-markdown`을 추가했으며 `pnpm audit`은 변경 전후 같은 39건(critical 2, high 13, moderate 18, low 6)을 보고했다. 신규 경고는 없고 기존 Next.js를 포함한 의존성 보안 갱신은 남아 있다. DB 마이그레이션은 이번 수정에서 변경하지 않았다.

통합 테스트는 로컬 Supabase만 허용하고 테스트 계정·사진을 정리한다. 외부 모델을 호출하지 않고 암호화, RLS, 인증·CSRF, 명시적 전체 검색, 준비 단계의 무변경, revision 충돌, 승인값 변조, 중복 확인, 기존 일괄 등록과의 동시성, 삭제 영향 변경, 공유 사진·정리와 사진을 보관한 계정 삭제를 검증한다.

별도 실제 연결 검증에서 개발용 키 암호화 가져오기, OpenAI 텍스트 검색 → 이동 초안 → 화면 확정, 테스트 이미지 분석 → 후보 편집 → 대화로 수량 정정 → 사진 보관·등록, 직접 다중 등록을 확인했다. Realtime WebRTC는 실제 OpenAI 연결과 도구 왕복을 테스트 오디오 스트림으로 확인했으며 실제 마이크를 녹음하지 않았다. 초기 구현에서 390px 모바일 화면의 모드 전환·초안 유지·가로 넘침도 확인했다.

채팅 전환 검증에서는 AI 응답을 테스트 값으로 대체하고 실제 로컬 저장 API를 사용했다. 검색 → 이동 확인 → 완료, 직접 등록, 사진 분석 후보 → 대상 선택 → 사진 보관·등록을 확인했다. 저장 응답을 의도적으로 끊은 뒤 같은 승인값으로 재시도해 중복 변경 없이 완료되는 것도 확인했다. 관리 창을 열고 닫아도 사진 수량이 유지되고, 사진을 추가하면 기존 초안을 보존한 채 현재 대화 위치로 이동한다. 한글 조합 중 Enter·Shift+Enter는 전송하지 않으며 음성 지원 실패를 두 번 겪어도 텍스트 입력이 동작한다. 390×844와 데스크톱 화면에서 가로 넘침 없이 대화 영역만 스크롤하고 하단 입력창이 유지된다.

추가 검증에서 “공구함에 있는거 책상에 좀 옮겨줘”를 별도 테스트 계정으로 실제 OpenAI에 요청해 보관함 조회 → 내용물 조회 → `move_items` 준비가 이어지는 것을 확인했다. `move_items`는 출발 보관함의 전체 물품 목록과 버전을 저장하고, 확정 때 정확한 목록 일치 여부를 다시 확인해 한 트랜잭션으로 이동한다. 1,001개 물품, 동시 재시도, 변경 충돌, 소유권과 사진 연결을 통합 테스트했다. 보관함 이름을 물품 검색으로 보낸 경우에도 보관함 후보를 반환하고, 중간 빈 결과 카드는 반복 표시하지 않는다. 이동 후 출발 보관함 목록에서 옮긴 물품을 제거한다.

브라우저 전사 검증은 가짜 녹음 장치와 전사 응답을 사용했다. 기본 마이크에서 전사만 호출되고 수동 전송 전 채팅·Realtime 호출은 0회, 음성 모드 버튼에서만 Realtime이 호출되는 것을 확인했다. 한글 조합 중 전사가 도착해도 최종 조합 뒤에 합쳐진다. 실제 마이크 음질과 전사 정확도는 기기에서 추가 확인해야 한다. 사용자 원본 기록은 조회만 했으며 테스트 계정·사진·키는 정리했다.

도우미 답변에는 안전한 마크다운 렌더러를 적용했다. 390px 모바일에서 강조·목록·코드가 표시되고 가로 넘침이 없으며, HTML과 위험한 링크·원격 이미지가 실행되거나 로드되지 않는 것을 검증했다. 사용자 입력은 원문 그대로 표시한다.

모델 분리 후 실제 Luna 호출로 신발장 공구함의 물품 이동안을 만들고 테스트 계정에서 확정한 뒤 다시 조회했다. 완료 영수증과 최신 장소 조회를 사용해 “공구함은 있지만 등록된 물품은 없음”이라고 답했으며, 보관함 자체가 없는 빈방과 구분했다. Terra는 별도 합성 이미지에서 책 1권·연필 2자루를 약 2.9초에 반환했고 빈 이미지에는 빈 후보를 반환했다. 최초 분석과 저장 사진 재분석은 같은 Terra 분석기를 사용한다. 실제 사용자 기록·사진은 이 검증에 사용하지 않았고 테스트 계정과 키는 정리했다.

실제 생활 사진 20–30장과 검색 질의 40–60개에 대한 모델 품질 평가는 아직 수행하지 않았다. 실제 iOS/Android 마이크·카메라와 한국어 음성 인식은 기기 검증이 필요하다. 의미 검색, 장기 작업, 새로고침 이후의 미저장 초안 복구는 명세의 후속 확장 범위로 남긴다.
