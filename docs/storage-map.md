# 보관 지도와 에이전트 장소 관리

`/storage`에서 격자로 집 배치를 만들고 물품 검색 답변의 미니맵으로 마지막 기록 위치를 확인합니다.
텍스트와 음성 에이전트가 같은 도구 결과를 사용합니다. 장소 생성, 수정, 삭제는 화면에서 변경안을 확인한 뒤 저장합니다.

## 사용 흐름

1. 상단 `지도`에서 저장본을 조회하고 `지도 만들기` 또는 `지도 편집`으로 진입
2. 빈 셀을 드래그하거나 시작 셀과 끝 셀을 입력해 사각 구획 선택
3. 기존 장소를 명시적으로 선택하거나 새 장소 이름 입력
4. 같은 장소에 속한 보관함을 구획 안의 셀에 배치
5. `변경 내용 확인`에서 전후 지도와 신규 장소, 해제할 표식 확인
6. 대화의 `저장 확인`으로 확정하고 완료 영수증 뒤 저장된 지도 확인

기존 구획은 드래그해서 옮깁니다. 구획을 선택하면 모서리와 테두리에 크기 조절 손잡이가 나타납니다.
이동할 때 내부 보관함 표식도 함께 이동합니다. 크기를 줄여 구획 밖으로 나간 표식은 미배치로 돌아가며 저장 전 변경안에서 확인할 수 있습니다.
겹치거나 지도 밖으로 벗어나는 배치는 적용하지 않습니다. 드래그 중 Esc를 누르거나 포인터 조작을 취소하면 원래 초안이 유지됩니다.
한 칸 이동과 너비, 높이 입력도 계속 사용할 수 있습니다.

“여권 어디 있어?”라는 요청은 물품 기록을 조회한 뒤 실제 미니맵을 답변에 첨부합니다.
표식 좌표가 없으면 장소 구획까지만 강조합니다. 여러 검색 결과 중 첫 물품의 지도를 먼저 표시하며 각 물품의 `지도에서 보기`로 다른 결과를 확인합니다.

채팅의 저장본 지도는 최대 144×96px, 제안과 승인 미리보기는 최대 240×160px의 미니맵입니다.
미니맵을 누르면 같은 좌표의 큰 지도를 확인합니다. 취소하거나 대체된 제안은 접어서 표시합니다.

물품 카드의 본문을 누르면 최신 상세 기록을 확인합니다. 설명, 수량, 보관 위치, 원본 사진, 사진 등록 시각과 물품 변경 시각을 표시합니다.
상세에서 지도 보기, 수정, 이동으로 이어갈 수 있습니다. 상세 열기와 창 복귀, 새로고침, 저장 완료 후 최신 기록을 다시 조회하며 삭제나 조회 실패를 구분합니다.

장소 관리 요청은 “서재라는 장소 만들어줘”, “서재를 작업방으로 바꿔줘”, “작업방 장소 삭제해줘”처럼 할 수 있습니다.
에이전트는 기존 장소의 실제 ID를 조회하고 변경안만 준비합니다. 말로 승인해도 화면 확인 없이 저장하지 않습니다.

## 저장과 상태

| 항목 | 처리 |
| --- | --- |
| 기본 지도 | 사용자당 1개, 기본 12×8칸, 최대 64×64칸 |
| 구획 | 최대 64개, 정수 좌표의 빈틈없는 사각형, 장소당 1개 |
| 신규 장소 | `client_location_key`로 초안 참조, 지도와 원자적 저장 |
| 보관함 표식 | 같은 장소 구획의 점유 셀 안에만 배치, 같은 셀의 여러 보관함 허용 |
| 변경 확인 | `storage_actions`의 revision, payload hash, idempotency key 재사용 |
| 동시 저장 | 같은 지도 revision에서는 하나만 성공, 나머지는 초안을 유지하고 재확인 |
| 응답 유실 | 동일 action ID로 결과 조회와 같은 작업 재시도 |
| 다른 변경안 | 지도 초안 유지, 기존 변경안 확정 또는 취소 전 지도 저장 대기 |
| 지도 조회 | 단일 DB 조회 스냅샷의 배치, 이름, 집계, 대상 경로와 버전 |
| 대화 수명 | 기존 페이지 상태와 동일, 새로고침 이후 대화나 초안 복구 없음 |

구획 삭제는 장소와 보관 기록을 삭제하지 않습니다.
장소 삭제는 연결된 구획과 표식을 정리하고 보관함의 장소를 미지정으로 바꿉니다. 보관함과 물품은 유지합니다.
기존 쓰기 경로에서 보관함을 삭제하거나 장소를 바꿔도 DB 트리거가 무효한 표식을 정리합니다.

## API와 도구

| 인터페이스 | 역할 |
| --- | --- |
| `GET /api/storage/map` | 인증된 사용자의 전체 지도와 장소, 보관함 집계 |
| `GET /api/storage/map/resolve?kind=item&id=UUID` | 물품, 보관함 또는 장소의 현재 경로와 지도 조회 |
| `POST /api/storage/map/propose` | 현재 기록과 상대 위치 조건을 사용한 미저장 배치 제안 |
| `GET /api/storage/items/UUID` | 소유한 물품의 최신 상세, 현재 보관 경로, 등록 사진 조회 |
| `POST /api/storage/actions`, `type=save_storage_map` | 지도 초안 검증과 고정된 승인 미리보기 생성 |
| 기존 action confirm, status, cancel 경로 | 저장, 결과 확인, 취소 |
| `show_storage_map` | 전체 지도 또는 조회한 실제 대상 ID의 읽기 전용 지도 이벤트 |
| `propose_storage_map` | 기본 배치 제안, 자연어 관계 추가와 정정, 명시적 관계 해제 |
| `search_items`, `get_container`, `get_location` | 기록 조회와 지도 카드 자동 첨부 |
| `prepare_change`의 장소 작업 | 장소 생성, 수정, 삭제 변경안 준비 |

지도 조회와 직접 편집에는 AI 키가 필요 없습니다.
에이전트 대화에는 기존 AI 설정을 사용합니다. 모델은 장소 사이의 의미 관계를 도구에 전달합니다. 서버가 격자 좌표를 계산하며 최종 저장은 화면에서 확정합니다.

## 자연어로 배치 제안

`지도` 카드나 지도 편집기의 `기본 배치 제안`으로 기존 장소와 보관함을 사용하는 초안을 만듭니다.
이 버튼에는 AI 키가 필요 없습니다. 등록된 장소가 없으면 거실, 주방, 침실, 현관을 예시로 추천합니다.
추천 장소와 보관함 표식은 실물 위치를 확인한 기록이 아니며 저장 전까지 DB를 변경하지 않습니다.

에이전트에는 다음처럼 요청할 수 있습니다.

- “있는 장소와 보관함으로 지도 초안을 만들어줘”
- “서재는 거실 왼쪽, 주방은 거실 위에 배치해줘”
- “서재를 거실 오른쪽으로 바꿔줘”
- “주방은 거실 옆 말고 위로 옮겨줘”
- “현관과 거실 사이의 위치 조건을 없애줘”
- “작은방과 신발장 사이에 화장실이 있고 오른쪽 벽에 붙어 있어. 거실은 가운데에 배치해줘”
- “주방은 거실 아래이면서 신발장 왼쪽이고, 주방 왼쪽에는 옷방과 옷방 베란다가 있어”

제안 카드에서 적용한 관계와 가정을 확인합니다. 필요하면 대화로 다시 수정하거나 `직접 편집`으로 조정합니다.
`변경 내용 확인`은 승인안을 준비하며, 이어서 `저장 확인`을 눌러야 지도와 신규 장소가 함께 저장됩니다.
보관함의 장소 소속은 자동 변경하지 않습니다. 소속이 없는 보관함은 장소를 지정한 뒤 배치할 수 있습니다.

위, 아래, 왼쪽, 오른쪽은 화면상의 관계입니다. ‘옆’은 같은 행에서 경계를 맞대는 좌우 배치로 해석하고 그 가정을 표시합니다.
‘사이’는 두 장소 사이의 가로 또는 세로 배치입니다. 방향을 말하지 않으면 기존 배치와 경계 조건을 참고한 가정을 표시합니다.
‘벽’과 ‘가운데’는 지도 격자의 경계와 중앙을 기준으로 제안합니다. 실측 벽이나 거리를 확인한 결과는 아닙니다.
집 구조를 설명하며 새로 언급한 장소도 미저장 신규 장소로 제안합니다. 복합 문장의 여러 조건과 나열한 장소를 각각 유지합니다.
순환하는 방향 조건, 겹침을 해결할 수 없는 크기, 동명 장소, 존재하지 않는 장소는 초안을 덮어쓰지 않고 오류 또는 구분 안내를 반환합니다.
다른 물품 변경안이 준비되어 있어도 로컬 배치 제안은 가능하며, 지도 저장은 기존 변경안을 확정하거나 취소한 뒤 진행합니다.

`POST /api/storage/map/propose`와 `propose_storage_map` 도구는 같은 배치 계산을 사용합니다.
입력은 상대 위치와 새 장소 이름이며 모델이 만든 셀, SVG, HTML을 실행하지 않습니다.
기존 초안 ID와 revision을 응답에 포함해 늦게 도착한 제안이 직접 편집한 내용을 덮어쓰지 않도록 합니다.

## 적용과 검증

앱을 배포하기 전에 `supabase/migrations/00014_storage_maps.sql`을 적용해야 합니다.
이 마이그레이션은 지도 테이블과 RLS, 무결성 검증, 참조 정리 트리거, 조회 RPC, 지도 확정 트랜잭션을 추가합니다.
기존 장소 삭제 승인안은 지도 영향이 달라졌다면 충돌로 처리하므로 최신 내용으로 다시 준비해야 합니다.

프로젝트의 Node 22와 pnpm 10.10.0 환경에서 다음 검증을 실행합니다.

```sh
pnpm lint
pnpm test
pnpm build
RUN_STORAGE_INTEGRATION=1 RUN_AGENT_INTEGRATION=1 TEST_APP_URL=http://localhost:4211 pnpm exec tsx --test tests/storage*.integration.test.ts tests/agent*.integration.test.ts tests/item-detail.integration.test.ts tests/location-tools.integration.test.ts tests/media-owner-cleanup.integration.test.ts
```

통합 테스트는 `.env.local`의 로컬 Supabase와 실행 중인 앱을 사용합니다.
테스트가 만든 계정과 데이터만 정리하며 DB 초기화는 필요하지 않습니다.
실제 텍스트 모델 검증은 `RUN_AI_MAP_INTEGRATION=1`을 명시하고 `tests/agent-map-narrative.integration.test.ts`를 실행합니다. 설정된 로컬 개발 키를 테스트 계정에 적용하며 외부 모델 호출이 발생합니다.

현재 범위는 사각 구획 편집, 자연어 배치 제안과 조회입니다. ㄱ자 구획, 여러 집과 층, 실측 축척은 포함하지 않습니다.
표식은 사용자가 배치한 마지막 기록이며 실물의 현재 위치를 자동으로 확인한 결과가 아닙니다.

## 검증 기록

2026-11-09, Node 22.18.0과 pnpm 10.10.0에서 확인한 결과입니다.

- 일반 테스트: 207개 통과, 외부 서비스 또는 통합 환경 조건부 테스트 17개 제외
- 로컬 저장소와 에이전트 통합 테스트: 28개 통과. 별도 실행한 실제 텍스트 모델 검증 1개 통과
- `pnpm lint`: 오류 없음, 기존 `container-form.tsx`의 React Hook Form 관련 경고 1개
- `pnpm build`: 성공
- 390px Chromium: 포인터 선택과 Esc, 역방향 좌표 입력, 기존 장소와 신규 장소 연결, 표식과 저장 확인 통과
- 채팅 조회: 실제 미니맵, 물품 이동 후 이전 카드의 최신 경로와 변경 표시 통과
- 상태 보호: 지도 선택 시 등록 대상 유지, 다른 물품 변경안 보호, 취소 응답 유실 후 취소만 재시도하는 흐름 통과
- 배치 제안: AI 키 없는 기본안, 추천 장소와 표식, 상대 위치 정정과 관계 해제, 확인 전 무저장 상태 검증 통과
- 제안 수명: 이전 카드 비활성화, 준비한 변경안 취소 후 편집, 늦은 응답 거부, 편집 후 버린 초안의 재적용 차단 통과
- 자연어 집 설명: 두 장소 사이, 경계, 중앙, 복합 방향 조건과 새 장소 후보를 모두 유지하는 초안 검증 통과
- 직접 편집: 마우스와 터치 드래그, 크기 조절 손잡이, 겹침과 범위 초과 거부, Esc와 포인터 취소, 잠금 중 미리보기 취소 검증 통과
- 큰 지도 편집: 이동과 크기 조절, 확대 후 스크롤 위치 유지와 선택한 구획의 수동 표식 배치 후 실제 저장 검증 통과
- 채팅과 상세: 미니맵의 크기 제한과 확대, 이전 제안 접힘, 물품 카드 키보드 진입, 원본 사진, 이동과 삭제 후 최신 상세 조회 검증 통과

브라우저 검증은 로컬 테스트 계정을 사용했으며 끝난 뒤 해당 계정을 정리했습니다.
에이전트 검증은 실제 인증된 도구 API와 모델 응답 대역을 사용했습니다. 첨부된 집 구조 문장은 실제 개발용 텍스트 모델로도 호출해 새 장소 6개와 배치 조건 8개의 반영을 확인했습니다. 외부 LLM 제공자를 통한 실시간 음성 통화는 이번 검증에 포함하지 않았습니다.
