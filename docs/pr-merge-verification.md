## 검증 결과

Node.js `22.18.0`, pnpm `10.10.0`과 로컬 Supabase를 사용했습니다.
커밋 대상 파일만 별도 디렉터리에 설치하고 `localhost:4202`의 프로덕션 서버를 대상으로 실행했습니다.

- 전체 테스트: 136개 통과, 실패와 건너뛰기 0개
- `pnpm lint`: 오류 0개, 기존 React Hook Form 경고 1개
- `pnpm build`: 타입 검사와 프로덕션 빌드 성공
- `supabase db lint --local --schema public --level error`: 통과
- `pnpm audit`: `low` 1건, `critical`, `high`, `moderate` 0건
- 모바일 390px: 비공개 대표사진 표시, 44px 크기와 원본 비율 유지, 가로 넘침 없음
- 사진 업로드 중 편집창 닫기: 새 초안 유지, 이전 업로드로 생성된 변경안 0개, 브라우저 오류 0개

브라우저 검증의 `networkidle` 대기는 종료되지 않아 실제 입력값, DB 변경안 수와 콘솔을 따로 확인했습니다.
음성 권한 대기와 업로드 취소는 별도 회귀 테스트 7개로도 검증했습니다.
사용자 원본 기록 대신 임시 계정과 합성 사진을 사용했습니다.

## 배포 조건과 남은 한계

앱 배포 전에 운영 DB에 `00008`부터 `00013`까지 여섯 마이그레이션을 순서대로 적용해야 합니다.
이번 작업에서는 로컬 DB에만 적용했습니다.

감사에 남은 `deepmerge@4.3.1`은 모든 사용 경로에 로컬 패치를 적용했지만 버전 판정 경고가 남습니다.
세부 범위는 [보안 수정 보고서](security-remediation.md)에 기록되어 있습니다.
Node 26은 [별도 전환 검증](node-26-readiness.md)만 수행했고 현재 런타임 요구 버전은 Node 22입니다.
